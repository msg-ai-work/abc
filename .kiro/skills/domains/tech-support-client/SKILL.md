# 기술지원(발송클라이언트) Domain Skill

## 적용 범위

- 고객사 발송클라이언트 설치/업그레이드
- 환경설정, 접속정보, 인증/권한, 네트워크 연계
- 파일/DB/API 기반 발송 연계
- 로그 수집 및 장애 진단
- OS/JDK/DB/네트워크 호환성 확인
- 고객 문의 재현, 가이드 작성, 원격/현장 지원

## 입력

- 고객/프로젝트 식별자는 비식별 ID 사용
- 클라이언트 버전
- OS/JDK/DB 등 실행 환경
- 접속 방식과 연계 유형
- 증상, 발생 시각, 오류 메시지
- 재현 여부와 최근 변경사항

## 판단 순서

1. 설치 문제인지 실행 문제인지 발송 연계 문제인지 분리한다.
2. 버전/환경 호환성을 먼저 확인한다.
3. 설정 → 네트워크 → 인증 → 입력 데이터 → 발송 요청 → 응답/결과 순서로 점검한다.
4. 고객 환경 문제와 미디어로그 시스템 문제를 분리한다.
5. 로그에서 최초 오류와 연쇄 오류를 구분한다.
6. 임시조치와 근본조치를 분리해 안내한다.

## 운영 체크리스트

- [ ] 클라이언트 버전 및 배포일 확인
- [ ] OS/JDK/DB 지원 조합 확인
- [ ] 설정파일 필수값/형식 확인
- [ ] DNS/방화벽/Port/TLS 연결 확인
- [ ] 계정·인증서·권한 유효성 확인
- [ ] 발송 요청이 실제 생성되는지 확인
- [ ] 응답 코드와 결과 코드 구분
- [ ] 로그의 최초 오류 시점 확인
- [ ] 최근 패치/환경변경 여부 확인
- [ ] 재현 절차와 고객 안내문 정리

## 개발/개선 체크리스트

- [ ] 반복 문의를 자동 진단 가능한 Rule로 변환
- [ ] 오류 메시지를 운영자가 이해할 수 있게 개선
- [ ] 설치/업그레이드 자동 점검 스크립트 검토
- [ ] 설정 누락/오류 사전검증 추가
- [ ] 버전 호환 Matrix 최신화
- [ ] 지원 결과를 FAQ/Runbook/Skill로 환류

## 산출물

- 기술지원 진단 결과
- 고객 안내 절차
- 재현 시나리오
- 설치/환경 점검표
- FAQ 또는 Skill 개선 PR

## 금지사항

- 고객 비밀번호, 인증서 개인키, 운영 DB 접속정보를 Git에 기록하지 않는다.
- 고객 환경에서 파괴적 명령이나 데이터 변경을 AI가 자동 실행하지 않는다.
- 원인이 확인되지 않은 상태에서 특정 시스템 책임으로 단정하지 않는다.
